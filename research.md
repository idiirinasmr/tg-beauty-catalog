# Исследование: Каталог услуг бьюти-мастера как Telegram Mini App

> Дата: 2026-03-10
> Проект: Каталог услуг бьюти-мастера как Telegram Mini App
> Флоу: Клиент открывает ТГ-бота → нажимает кнопку → видит услуги с ценами и кнопкой «Выбрать»

---

## 1. Примеры Telegram Mini App в бьюти-нише и смежных нишах

### 1. DurgerKingBot (демо от Telegram)

**Что делает:** Эталонное демо-приложение от команды Telegram — витрина с каталогом товаров, выбор, корзина, оформление заказа. Открытый исходный код.

**Сильные стороны:**
- Эталонная реализация от самих разработчиков Telegram
- Плавная интеграция с нативным интерфейсом (темы, кнопки)
- Простой флоу: каталог → выбор → корзина → оплата
- Поддержка Telegram Payments
- Haptic feedback (вибрация) при добавлении в корзину
- Анимации при переходах между экранами

**Слабые стороны:**
- Упрощённый каталог, нет фильтров и поиска
- Нет категорий и подкатегорий
- Нет профилей и истории заказов
- Не подходит для записи на время

**Что можем сделать лучше:**
- Добавить категории услуг
- Красивые карточки с фото и описанием
- Прямая связь с мастером после выбора

---

### 2. YCLIENTS (интеграция с Telegram)

**Что делает:** CRM для бьюти-индустрии с интеграцией через Telegram Mini App — онлайн-запись в салоны красоты, выбор мастера и времени.

**Сильные стороны:**
- Полноценный флоу записи: услуга → мастер → дата/время → подтверждение
- Интеграция с CRM и календарями мастеров
- Автоматические напоминания через бота
- Большая база салонов

**Слабые стороны:**
- Перегруженный интерфейс, слишком много шагов
- Медленная загрузка (тяжёлый фреймворк)
- Шаблонный дизайн «под всех» — нет индивидуальности
- Платная подписка для мастера

**Что можем сделать лучше:**
- Лёгкий, быстрый интерфейс без лишних шагов
- Персонализированный дизайн под конкретного мастера
- Бесплатное решение без ежемесячной подписки

### 3. SalonBot / BookingBot (конструкторы ботов)

**Что делает:** Платформы-конструкторы Telegram-ботов с Mini App для записи в салоны красоты — готовые шаблоны без кода.

**Сильные стороны:**
- Быстрый запуск без программирования
- Готовые шаблоны для бьюти-ниши
- Встроенная аналитика и CRM
- Приём оплаты (ЮKassa, Stripe)

**Слабые стороны:**
- Ограниченная кастомизация — все витрины выглядят одинаково
- Зависимость от платформы (данные у них)
- Платные тарифы за расширенный функционал
- Может «тормозить» из-за универсальности

**Что можем сделать лучше:**
- Уникальный дизайн, не шаблонный
- Полный контроль над данными
- Мгновенная загрузка за счёт лёгкого кода

### 4. Конструкторы витрин (SendPulse / Botostore)

**Что делает:** Платформы для создания Mini App-витрин без кода — каталоги товаров и услуг, онлайн-запись, приём оплаты.

**Сильные стороны:**
- Каталог с категориями, фото, описаниями, ценами
- Свайп-галереи фото
- «Плавающая» кнопка записи внизу экрана
- Фильтры по категориям (горизонтальные вкладки)
- Интеграция отзывов и рейтингов

**Слабые стороны:**
- Шаблонный дизайн — все выглядят одинаково
- Зависимость от сторонней платформы
- Платные тарифы
- Ограниченная кастомизация

**Что можем сделать лучше:**
- Своё решение = полный контроль
- Минимализм вместо перегруженности
- Фокус на одном мастере, а не на маркетплейсе

### 5. Сервисные боты с Mini App (банки, клиники, фитнес)

**Что делает:** Боты, использующие Mini App для каталога услуг и онлайн-записи — выбор услуги, локации, даты/времени.

**Сильные стороны:**
- Полноценный флоу записи с прогресс-баром
- Карточки услуг с иконками и описанием
- Интерактивный календарь для выбора даты
- Уведомления о записи

**Слабые стороны:**
- Перегруженный интерфейс
- Медленная загрузка
- Не всегда адаптированы под разные экраны

**Что можем сделать лучше:**
- Простой интерфейс в 3-4 шага максимум
- Мгновенная загрузка
- Адаптация под все устройства

| 3 | **Подтверждение** | Сводка: услуга, цена — кнопка «Подтвердить» |
| 4 | **Успех** | Экран подтверждения — «Мастер получил вашу заявку!» |

### Дополнительные экраны (v2)

| # | Экран | Описание |
|---|-------|----------|
| 5 | **Выбор даты/времени** | Календарь + доступные слоты |
| 6 | **Мои записи** | Предстоящие и история |

| 8 | **Профиль** | Данные клиента |
| 9 | **Отзывы** | Отзывы о мастере/услугах |
| 10 | **Оплата** | Интеграция с Telegram Payments |

### Рекомендуемая навигация (MVP)

```
Клиент нажимает кнопку в боте
    ↓
Главная (каталог услуг с ценами)
    ↓ нажимает «Выбрать»
Подтверждение (услуга + цена + кнопка «Отправить заявку»)
    ↓ нажимает MainButton
Успех («Мастер получил заявку, свяжется с вами!»)
    ↓ автоматически
Бот отправляет мастеру сообщение с деталями
```

## 4. Обязательные UI-элементы

### Нативные компоненты Telegram

| Элемент | Что делает | Как используем |
|---------|-----------|----------------|
| **MainButton** | Главная кнопка внизу экрана | «Выбрать» → «Подтвердить» → «Отправить заявку» |
| **BackButton** | Кнопка «Назад» в заголовке | На всех экранах кроме главного |
| **HapticFeedback** | Вибрация при нажатиях | При выборе услуги и подтверждении |
| **Popup / Alert** | Нативные окна | Подтверждение действий |
| **Theme adaptation** | Светлая/тёмная тема | Автоматически из Telegram |

### CSS-переменные темы Telegram (обязательно использовать)

```css
var(--tg-theme-bg-color)            /* фон */
var(--tg-theme-text-color)          /* текст */
var(--tg-theme-hint-color)          /* подсказки */
var(--tg-theme-link-color)          /* ссылки */
var(--tg-theme-button-color)        /* кнопки */
var(--tg-theme-button-text-color)   /* текст кнопок */
var(--tg-theme-secondary-bg-color)  /* вторичный фон (карточки) */
```

### Обязательные вызовы API

```javascript
Telegram.WebApp.ready()          // Сообщить Telegram, что приложение загружено
Telegram.WebApp.expand()         // Раскрыть на весь экран
Telegram.WebApp.MainButton       // Главная кнопка
Telegram.WebApp.BackButton       // Кнопка назад
Telegram.WebApp.HapticFeedback   // Вибрация
Telegram.WebApp.sendData()       // Отправить данные в бот
Telegram.WebApp.close()          // Закрыть приложение
```

## 5. Best Practices для нашего приложения

### Дизайн
- Следовать теме Telegram (светлая/тёмная) через `themeParams`
- Минималистичный интерфейс — как в самом Telegram
- Скруглённые углы (border-radius 12-16px)
- Системный шрифт (не кастомные)
- Стандартные отступы 16px по бокам
- Карточки с фоном `secondary_bg_color`

### Навигация
- **MainButton** для основного действия на каждом экране
- **BackButton** вместо собственной кнопки «назад»
- Табы (если нужны) — вверху, не внизу (там MainButton)
- Максимум 3-4 шага до завершения действия
- Поддерживать свайп назад (не блокировать жесты)

### Производительность
- Загрузка менее 2-3 секунд
- Минимальный бандл (< 1-2 MB)
- Skeleton-экраны при загрузке данных
- CloudStorage API для сохранения состояния

### Взаимодействие
- HapticFeedback при ключевых действиях
- MainButton меняет текст по контексту экрана
- Показывать `showProgress()` при загрузке на MainButton
- Нативные попапы (`showPopup`, `showConfirm`) вместо кастомных модалок

## 6. Ограничения платформы (учитываем при разработке)

| Ограничение | Как учитываем |
|-------------|---------------|

| Пользователь может закрыть свайпом | Сохранять состояние в CloudStorage |
| Нет надёжного localStorage | Использовать CloudStorage для важных данных |
| Разные платформы (iOS/Android/Desktop) | Тестировать на всех |
| Размер бандла | Лёгкий код, минимум зависимостей |

| Пользователь может свернуть окно | Обработка `viewportChanged` |
| Версии API | Проверять `Telegram.WebApp.version` |

## 8. Экспертная оценка

### 8.1 UX-дизайнер (10 лет в мобильных интерфейсах)

#### Что новички делают неправильно в Mini App

**1. Копируют обычный сайт в Mini App.**
Mini App — это не сайт. Здесь нет привычной навигации, нет адресной строки, экран маленький. Нельзя просто «ужать» веб-страницу.
> Решение: Проектировать под Mini App с нуля. Один экран — одна задача. Никаких боковых меню, футеров, хедеров.

**2. Делают свои кнопки вместо MainButton.**
Пользователь Telegram привык к нативной кнопке внизу. Своя кнопка поверх — это визуальный шум и путаница.
> Решение: Всегда использовать `MainButton` для основного действия. Она уже стилизована под тему пользователя, он знает, где она.

**3. Слишком много информации на одном экране.**
Каталог с 20 услугами, описаниями, фото, ценами, отзывами — всё сразу. Пользователь теряется.
> Решение: Карточки услуг — компактные. Название + цена + маленькое фото. Детали — по нажатию. Максимум 5-7 карточек видно без скролла.

**4. Игнорируют тёмную тему.**
50%+ пользователей Telegram используют тёмную тему. Если Mini App — белый, это слепит и выглядит чужеродно.
> Решение: Обязательно использовать CSS-переменные Telegram. Приложение должно автоматически адаптироваться.

**5. Забывают про BackButton.**
Пользователь нажал на услугу, открылись детали — а назад вернуться нельзя. Только закрыть и открыть заново.
> Решение: `BackButton.show()` на каждом экране кроме главного. `BackButton.onClick()` — возврат на предыдущий.

**6. Нет обратной связи при действиях.**
Нажал «Записаться» — ничего не произошло. Или произошло, но непонятно что.
> Решение: HapticFeedback при каждом действии. Анимация на кнопке. Экран успеха с чёткой надписью.

**7. Мелкие тап-зоны.**
Кнопки 30x30px — мимо попадаешь пальцем.
> Решение: Минимум 44x44px для любого интерактивного элемента. Это стандарт Apple и Google.

#### Что обязательно должно быть

| Элемент | Зачем |
|---------|-------|
| Компактные карточки услуг | Быстрый обзор без перегрузки |
| Цена на видном месте | Главный критерий выбора для клиента |
| Фото услуги/результата | Визуал продаёт лучше текста |
| Кнопка «Записаться» | Очевидное действие без раздумий |
| Экран подтверждения | Клиент видит, что именно выбрал |
| Экран успеха | Уверенность, что заявка отправлена |
| Адаптация к теме | Приложение не выглядит «чужим» |

#### Что бесит пользователей в Mini App

1. **Долгая загрузка** — белый экран 3+ секунды = закрыл
2. **Мерцание при загрузке** — контент прыгает, подгружается кусками
3. **Нет способа вернуться назад** — только закрыть
4. **Кнопки не реагируют** — нажал, а ничего не происходит
5. **Приложение не помнит состояние** — закрыл случайно, открыл — всё сначала
6. **Текст не читается** — мелкий шрифт, плохой контраст
7. **Модальные окна поверх модальных окон** — вместо нативных попапов
8. **Горизонтальный скролл** — в мобильном приложении это неестественно
9. **Невозможно скопировать текст** (цену, адрес) — раздражает
10. **Нет подтверждения отправки** — «а мастер вообще увидел?»

### 8.2 Маркетолог (специалист по конверсии в мессенджерах)

#### Что заставит клиента записаться

**1. Цена — сразу и честно.**
Главная причина, почему клиент открывает каталог — узнать цену. Если цена спрятана или «по запросу» — он уходит. В бьюти-нише цена = решающий фактор.
> Рекомендация: Цена крупным шрифтом на каждой карточке. Если есть диапазон — «от 1500 ₽».

**2. Фото результата, а не процесса.**
Клиенту не интересно видеть кресло или инструменты. Ему интересен результат: красивые ногти, укладка, макияж.
> Рекомендация: Фото «до/после» или готовый результат. Качественные, не стоковые.

**3. Минимум шагов до записи.**
Каждый лишний шаг — минус 20-30% конверсии. Идеал для MVP: выбрал услугу → подтвердил → готово.
> Рекомендация: 2-3 нажатия максимум. Не просить логин, регистрацию, заполнение анкеты.

**4. Социальное доказательство.**
Даже одна строка «Записались 47 человек за месяц» или «★ 4.9» повышает доверие.
> Рекомендация: На v2 добавить мини-отзывы или счётчик записей.

**5. Срочность и доступность.**
«Свободно сегодня» или «Осталось 2 окна на эту неделю» — мощный триггер.
> Рекомендация: На v2 показывать ближайшее свободное время.

#### Элементы, повышающие конверсию

| Элемент | Влияние на конверсию | Приоритет |
|---------|---------------------|-----------|
| Цена на карточке | +40-60% | MVP |
| Фото результата | +25-35% | MVP |
| Кнопка «Записаться» (не «Подробнее») | +15-20% | MVP |
| Имя и фото мастера | +10-15% | MVP |
| Длительность процедуры | +5-10% | MVP |
| Отзывы/рейтинг | +20-30% | v2 |
| «Свободно сегодня» | +15-25% | v2 |
| Акции/скидки | +10-20% | v2 |
| Счётчик записей | +5-10% | v2 |
| Гарантия (бесплатная переделка) | +10-15% | v2 |

#### Текст кнопок — что работает, а что нет

| Плохо | Хорошо | Почему |
|-------|--------|--------|
| «Отправить» | «Записаться» | Конкретное действие |
| «Подробнее» | «Выбрать» | Ведёт к цели, а не к чтению |
| «Заказать» | «Записаться на [услугу]» | Персонализация |
| «OK» | «Готово, жду ответа!» | Эмоция + ожидание |
| «Далее» | «Подтвердить запись» | Понятно, что произойдёт |

#### Воронка записи в Telegram

```
ВХОД (бот)
    → Приветствие + кнопка «Посмотреть услуги»
    → Открывается Mini App

ИНТЕРЕС (каталог, 3-5 сек)
    → Клиент видит карточки с фото, ценами
    → Сканирует глазами, выбирает

РЕШЕНИЕ (1-2 сек)
    → Нажимает «Записаться» на нужной услуге

ПОДТВЕРЖДЕНИЕ (2-3 сек)
    → Видит сводку: услуга, цена, мастер
    → Нажимает MainButton «Подтвердить запись»

УСПЕХ
    → «Мастер получил вашу заявку! Ответит в течение 15 минут»
    → Mini App закрывается
    → Мастер пишет клиенту в Telegram
```

**Общее время от открытия до записи: 10-15 секунд.** Это идеал.

#### Ошибки, убивающие конверсию в бьюти-нише

1. **Нет цены** — «узнать в ЛС» = потеря 60-70% клиентов
2. **Стоковые фото** — клиент чувствует подвох
3. **Требуют номер телефона** — Telegram уже знает пользователя
4. **Нет описания длительности** — клиент не может планировать время
5. **Слишком много услуг без категорий** — каталог из 50 пунктов без структуры
6. **Нет фото мастера** — в бьюти люди идут к человеку, не к услуге
7. **Сложная запись** — 5+ шагов, календарь, выбор времени для MVP — лишнее
8. **Нет подтверждения** — клиент не уверен, что заявка дошла

### 8.3 Telegram-разработчик (3 года опыта с Bot API и Mini Apps)

#### Что работает хорошо в Telegram Mini App

**1. `sendData()` — отправка данных в бота.**
Самый простой способ передать выбор клиента мастеру. Клиент выбрал услугу → `sendData({service: "Маникюр", price: 1500})` → бот получает → пересылает мастеру.
> Ограничение: работает только если Mini App открыт через кнопку `web_app` в боте (не через меню). Данные приходят как `web_app_data` в хендлер бота.

**2. Темизация через `themeParams`.**
Приложение автоматически подстраивается под тему Telegram. Не нужно угадывать цвета — они приходят от клиента.

**3. `initDataUnsafe.user` — данные пользователя.**
Имя, фото, ID — доступны сразу. Не нужно просить регистрацию. Можно сразу персонализировать: «Привет, Анна!»

**4. `MainButton` + `HapticFeedback`.**
Делают приложение нативным. Пользователь не чувствует, что это веб-страница.

**5. `CloudStorage` — хранение данных.**
До 1024 ключей. Можно сохранять избранные услуги, историю, незавершённый выбор.

#### Что лучше НЕ делать

**1. Не использовать тяжёлые фреймворки для MVP.**
React, Vue, Angular — оверкилл для каталога из 10-15 услуг. Добавляют 100-300KB к бандлу, замедляют загрузку.
> Рекомендация: Чистый HTML + CSS + vanilla JS. Для MVP этого достаточно. Размер бандла < 50KB.

**2. Не делать SPA с роутером.**
В Mini App нет адресной строки, нет смысла в URL-маршрутизации. Достаточно скрывать/показывать div-секции.
> Рекомендация: Простые «экраны» — `div` с `display: none/block`. BackButton переключает между ними.

**3. Не запрашивать данные, которые Telegram уже даёт.**
Имя, аватар, ID — уже есть. Не нужно просить «Введите имя».

**4. Не игнорировать `expand()`.**
Без вызова `expand()` Mini App открывается как маленький bottom sheet. Нужно раскрыть на весь экран сразу.

**5. Не забывать валидировать `initData` на сервере.**
Для MVP без бэкенда это не критично, но для продакшена — обязательно. Иначе любой может подделать запрос.

**6. Не использовать `alert()` / `confirm()`.**
Стандартные JavaScript-алерты блокируют поток и выглядят чужеродно.
> Рекомендация: `Telegram.WebApp.showPopup()` — нативные, красивые, не блокирующие.

**7. Не забывать про `ready()`.**
Без вызова `ready()` Telegram продолжает показывать загрузочный экран. Приложение выглядит зависшим.

#### Технические ограничения и обходные пути

| Проблема | Решение |
|----------|---------|
| `sendData()` работает только один раз за сессию | Если нужно отправлять несколько раз — использовать бот API через fetch к своему серверу |
| `sendData()` ограничен 4096 байтами | Для каталога достаточно: JSON с ID услуги, ценой, именем |
| Mini App закрывается после `sendData()` | Это ожидаемое поведение — после отправки заявки закрытие логично |
| Нет push-уведомлений из Mini App | Уведомления отправляет бот, не Mini App |
| Нет доступа к камере | Не нужно для каталога услуг |
| `localStorage` может очиститься | Критичные данные — в `CloudStorage` |
| Разное поведение на iOS/Android/Desktop | Тестировать на всех. На Desktop окно шире — адаптировать |

#### Рекомендуемый технический стек для MVP

```
Frontend (Mini App):
├── index.html          — один файл, все экраны
├── style.css           — стили с CSS-переменными Telegram
├── app.js              — логика переключения экранов, sendData
└── telegram-web-app.js — SDK Telegram (подключается через <script>)

Backend (Telegram Bot):
├── bot.py / bot.js     — бот на Python (aiogram) или Node.js
├── Обработка web_app_data
├── Пересылка заявки мастеру
└── Хостинг: любой VPS или serverless (Vercel, Railway)

Хостинг Mini App:
├── GitHub Pages (бесплатно, HTTPS из коробки)
├── или Vercel / Netlify
└── HTTPS обязателен — Telegram не загрузит HTTP
```

#### Порядок разработки

```
1. Создать бота через @BotFather
2. Настроить Menu Button → ссылка на Mini App
3. Захостить HTML-страницу с каталогом (GitHub Pages)
4. Подключить telegram-web-app.js
5. Сделать каталог с карточками услуг
6. Реализовать sendData() при выборе услуги
7. Написать бота, который принимает web_app_data
8. Бот пересылает заявку мастеру
9. Протестировать на iOS, Android, Desktop
```

### 8.4 Сводные рекомендации (консенсус трёх экспертов)

#### Единогласно: что ОБЯЗАТЕЛЬНО для MVP

1. **Карточки услуг** — фото + название + цена + кнопка «Записаться»
2. **Цена на видном месте** — крупно, без «по запросу»
3. **2-3 нажатия до записи** — каталог → подтверждение → успех
4. **MainButton + BackButton** — нативные элементы Telegram
5. **Адаптация к теме** — светлая/тёмная автоматически
6. **HapticFeedback** — вибрация при ключевых действиях
7. **Экран успеха** — «Мастер получил заявку, ответит в течение 15 минут»
8. **Быстрая загрузка** — менее 2 секунд, бандл < 50KB
9. **Фото мастера + имя** — в шапке или на главном экране
10. **Длительность процедуры** — рядом с ценой

#### Единогласно: чего НЕ делать в MVP

1. **Не требовать регистрацию** — Telegram уже знает пользователя
2. **Не делать календарь записи** — это v2, для MVP достаточно заявки
3. **Не использовать тяжёлые фреймворки** — vanilla JS достаточно
4. **Не ставить стоковые фото** — только реальные работы мастера
5. **Не делать корзину** — для одной услуги она не нужна
6. **Не создавать свои кнопки внизу экрана** — там MainButton
7. **Не игнорировать мобильные экраны** — 95%+ откроют с телефона
8. **Не прятать цену** — это убийца конверсии №1
9. **Не делать горизонтальный скролл** — неестественно для мобильных
10. **Не забывать про `ready()` и `expand()`** — без них приложение выглядит сломанным

#### Приоритеты на старте

| Приоритет | Задача | Эксперт |
|-----------|--------|---------|
| 1 | Каталог услуг с фото и ценами | UX + Маркетолог |
| 2 | Кнопка «Записаться» → sendData → бот → мастер | Разработчик |
| 3 | Адаптация к теме Telegram (свет/тёмн) | UX + Разработчик |
| 4 | Экран подтверждения и успеха | UX + Маркетолог |
| 5 | HapticFeedback + MainButton + BackButton | UX + Разработчик |
| 6 | Фото и имя мастера | Маркетолог |
| 7 | Длительность процедуры на карточке | Маркетолог |
| 8 | Тестирование на iOS/Android/Desktop | Разработчик |

#### Метрики успеха MVP

| Метрика | Целевое значение |
|---------|-----------------|
| Время загрузки | < 2 секунд |
| Время от открытия до записи | < 15 секунд |
| Количество шагов до записи | 2-3 нажатия |
| Размер бандла | < 50 KB |
| Конверсия (открыл → записался) | 15-25% |
| Процент отказов | < 30% |

#### Главный вывод

> **Сила этого MVP — в простоте.** Конкуренты перегружены функциями: календари, CRM, оплата, рассылки. Для клиента, который хочет записаться к мастеру, это лишний шум. Наш каталог решает одну задачу — показать услуги и дать записаться в два нажатия. Это быстрее, проще и приятнее, чем любой конструктор.
